## 目标

把本地仓库中的官方资产（即 frontmatter tags 中包含 model 或 example 的文件）同步到 https://github.com/lesslive/LessLive 的 main 最新版本，保留用户资产，同步完成后提交。不自动 push。

## 规则

- 官方资产：以上游路径为准，不看本地状态。
- 根目录 README.md 归用户，不纳入同步。
- 同步清单之外的文件，一律不动、不删。
- 官方资产无条件覆盖本地版本，不合并、不保留本地修改。
- 官方已删除或重命名的旧文件，本地保留，报告中告知用户，提醒用户手动删除
## 步骤

1. 检查起点

确保  `git status` 必须干净，且不在未完成的 Git 操作中、在分支上。不满足就停止，不自动提交、暂存或 stash。

2. 固定上游版本
确认 upstream 指向官方仓库，`git fetch upstream`，记录 `upstream/main` 的提交号作为本次目标。

3. 还原官方资产

从目标提交还原文件到工作区。只动工作区，不暂存、不提交、不切分支、不 merge、不 pull。

4. 检查状态、校验并提交

执行 `git status`：
- 如果工作区干净，报告【官方资产已是最新版本，无需更新】并结束流程；
- 如果有变更，确认 README.md 未变。

执行git add -A，git commit，报告提交号和变更清单。不 push。

## 操作配置：
### 仓库配置

```
1. 检查你当前的远程配置
git remote -v
（此时你可能只会看到 origin 指向你自己的仓库，或者指向官方仓库）

2. 把官方仓库设为上游，即可获得更新能力执行：
git remote add upstream https://github.com/lesslive/LessLive.git

3. 如果你想把自己的个人仓库也同步到 GitHub 做灾备（可选），可以修改 origin：
git remote set-url origin 你自己的仓库地址

4. 再次确认，你应该能看到 origin（你自己的）和 upstream（官方的）：
git remote -v
```

### 执行升级

```
# 1. 拉取最新
git fetch upstream

# 2. 执行更新
git checkout upstream/main -- . ':(exclude)README.md'

# 3. 检查状态
git status
# （你会看到它们都在“暂存区”，而“未暂存”区域是干净的）

# 4. 直接提交
git commit -m "同步官方资产至最新版本"

# 5. 然后推送（可选）
git push
```
